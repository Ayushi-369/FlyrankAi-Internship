Can a model flag declining pages better than an age rule?

  • By Ayushi
  • September 2026
  • Code and notebooks on GitHub

1Abstract

Content teams need to know which published pages are losing search visibility, and a common rule of thumb flags old pages that rank on page one with weak click-through. We studied 30,000 pages from 32 pseudonymized clients in the FlyRank ML Internship dataset, labelling a page as declining when its search impressions fell more than 20% between two consecutive 30-day windows (54% of pages). We compared that rule with a small random forest on five page-level features, using five-fold cross-validation grouped by client so every test page came from a client the model had never seen. The model's top-10% review queue was 67% declining on average (55–81% across folds), against 53% for the rule and 54% for random ordering, and it beat the rule in all five folds. The lift is real but modest, so we present the model as a decision-support queue for editors rather than a predictor of recovery.

Correction to an earlier draft. A previous version of this work reported 0.99 precision. That number came from label leakage: the label was a freshness tier computed directly from days_since_last_update, which was also a model feature. A one-line rule reproduces that label on 100% of rows. Every number on this page uses the corrected label, and the check is in the notebook.

2Introduction

Picture a content lead with 3,000 published articles and enough writer time to revisit about 300 of them this month. Some pages are quietly losing search impressions; others are stable or growing. Every rewrite spent on a healthy page is an hour not spent on one that is slipping.

The usual shortcut is age: refresh what is old, especially old pages that rank well but earn few clicks. Our Week-4 baseline encoded exactly that. The question for this paper is whether a small learned model, tested on clients it never trained on, can order the review queue better than that rule.

The data gave the rule a problem before any model was trained. In this slice, older pages were less likely to be declining, not more.

3Data

We used the anonymized starter slice of the FlyRank ML Internship dataset: one row per content item, with search and engagement metrics aggregated over a trailing 90-day window ending at export. The larger ~79-million-row warehouse release was not used for this paper; extending the work to it is listed as a next step.

4Methodology

Assumptions

We assume a page's current 90-day metrics describe its state well enough to rank it for human review, and that clients differ enough that a useful model must work on clients it has not seen. We do not assume that a flagged page will recover if refreshed.

Features

Five page-level features: content age in days, days since last update, average search position, click-through rate and engagement rate. Rates are stored as percentages, so a CTR value of 0.76 means 0.76%.

Baseline

The Week-4 rule scores a page 90 if it is older than 365 days, ranks in positions 1–10 and has CTR under 2%; 60 if it is older than 500 days; 50 if it ranks 1–10 with CTR under 2%; otherwise 0. The original code compared CTR with 0.02 instead of 2.0 (CTR is stored in percent), so it tested for 0.02%. We fixed the unit here so the baseline gets a fair test. Ties in the rule's score are broken at random.

Model

A random forest with 300 trees, maximum depth 6, at least 20 pages per leaf, balanced class weights and seed 42. It is deliberately small, so its behaviour stays close to what the features can support.

Validation design

Five-fold cross-validation grouped by client (GroupKFold): every page in a test fold belongs to a client that contributed nothing to training. This asks the question a new client would ask: does the ranking work on my pages? The main metric is precision in the top 10% of each fold's queue, which is the share of pages an editor reviews that are truly declining. ROC-AUC is reported alongside as an overall ranking measure. Model and rule are scored on the same folds.

5Results

On clients it had never seen, the model's top-10% queue contained 67% declining pages. Random ordering would give 54%, and the rule gave 53%, which is no better than chance.

The lift holds across queue sizes. It peaks around the top 10% and narrows as the queue grows toward half of all pages, which is what a useful ranking should look like.

What the model leans on

Averaged across folds, average search position carried the most weight (0.43 of feature importance), followed by content age (0.33), days since last update (0.12), CTR (0.10) and engagement rate (0.02). Descriptively, pages ranking 11–20 declined most often (61%) and pages in the top three positions least often (24%). Pages not updated in 91 or more days declined more often than recently updated ones, 61% against 51%.

6Limitations and honest framing

  • The lift is modest and uneven. An AUC of 0.61 is a weak-to-moderate ranking signal, and fold results range from 0.55 to 0.81 precision. In one of five folds the model's top 10% was no better than that fold's base rate. Treat the model as an ordering aid, not a verdict.
  • Feature and label windows overlap. CTR, position and engagement are 90-day aggregates that include the 30-day label window. They are not the label, but they are not strictly earlier than it either. A forward-window design on the warehouse release would be stronger.
  • The label is short-term. A 20% fall between two 30-day windows includes seasonality and noise, not only lasting decay.
  • No causal claim. This is one cross-sectional snapshot. Nothing here shows that refreshing a flagged page will restore its traffic.
  • Small, uneven sample. 32 clients, one holding about a quarter of all pages. Results may shift on the full release or on clients with different content mixes.

7Ranked recommendations

Ordered by expected value for an editorial team, given the evidence above.

  1. Order the weekly review queue by model score, not by age.

    Reviewing the top 10% by model score surfaced declining pages 67% of the time on unseen clients, against 53% for the age rule.

  2. Retire age as a standalone decay signal.

    The oldest quartile declined least often in this data (42%). Age still helps inside the model, but only in combination with position.

  3. Within the queue, look first at stale pages ranking 11–20.

    Pages not updated in 91+ days (61% declining) and pages in positions 11–20 (61%) showed the highest observed decline rates.

  4. Keep an editor in the loop and log every decision.

    Record accept or reject for each flagged page. That log is the real-world precision check this offline study cannot provide.

  5. Revalidate on the warehouse release before scaling.

    Rebuild features strictly before a forward label window, and confirm the lift holds across more clients.

8Reproducibility

Every number on this page is produced by one notebook, run top to bottom with seed 42 and scikit-learn's GroupKFold (5 folds).

  • Capstone notebook: work/notebooks/capstone.ipynb, or open it in Colab and choose Run all.
  • Weekly working notebooks (question, data contract, baseline, model, validation audit, playbook): work/notebooks/
  • Repository: github.com/Ayushi-369/FlyrankAi-Internship

To rerun locally: clone the repository, install requirements.txt, and run the capstone notebook from work/notebooks/. It reads the dataset from data/raw/ and writes the top-10% queue (pseudonymous IDs only) to work/outputs/.
